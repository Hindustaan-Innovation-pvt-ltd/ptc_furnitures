How PTC Furnitures Works

1. Instant Catalog Browsing

The storefront layouts (`/collections`, `/catalogs`) serve pre-compiled static layouts instantly, then stream in live MongoDB products list via async Suspense components.

2. Smart Image Optimization

Uploads pass through the Sharp engine: white backgrounds are keyed out with smooth feathering, and standard 800x800 transparent canvas watermarks are added in the center.

3. Brand Watermark Synchronization

When an admin changes a brand's logo or opacity in the dashboard settings, the app runs a background process re-processing all products under that brand using saved original images.

4. Leads & Client Connect

Interactions like catalog downloading or dealer registration trigger automated Twilio SMS alerts & automated WhatsApp business notifications to backend admins.

Next.js 16 Fixes (Coolify)

No connection() in API

Removed `connection()` from all GET route handlers. Thrown dynamic exceptions was causing API crashes.

Isolated Suspense Shells

Wrapped all storefront databases queries into nested React Server components. Static layouts load instantly while database streams load.

Safe Brand Fallbacks

MongoDB records missing the `brand` property now resolve with a default `""` string fallback, avoiding `.trim()` on undefined errors on admin dashboards.

Standalone Server Operation

When compiled, Next.js outputs a production-ready node server containing all routing layers. Next.js App Router renders pages on the server as Server Components and serves them as dynamic client hydration paths.

Direct MongoDB queries are initiated directly from Server Components via the mongoose connector library (`src/lib/mongodb.ts`), omitting extra API network layers for fast database-to-HTML rendering.

Dynamic Assets Processing

The standalone server performs real-time media transformations via sharp module dependencies. White backgrounds on furniture photos are stripped out locally, and brand watermark overlays are composite-merged.

Pristine images are kept as references in `/public/upload/*_original.png` so that watermarks can be rebuilt on-the-fly dynamically when global brand logo preferences are modified.

Next.js 16 Storefront Routing & Hydration Flow

Understanding Partial Prerendering (PPR) dynamic connection bounds and asynchronous React server component streaming.

Partial Prerendering (PPR) Concept

Next.js 16 leverages **Partial Prerendering (PPR)** to bundle static shells during build compilation. In this app, layout parts like headers, navigation links, and footers are compiled as static files.

When a user navigates to `/collections` or `/catalogs`, Next.js responds with the static HTML shell in 0ms (prefetched on hover), providing an instant loading visual.

The 500 Route Crash Resolution:
Next.js requires dynamic server functions (like `connection()`) to be wrapped inside a `` boundary. When `connection()` was called in the page root, Next.js crashed as it couldn't prerender the page shell. Moving `await connection()` inside the async loader component fixed this behavior.

Page Hydration Lifecycle

Step 1: Prefetch on Hover

Client hovers over storefront page links. The static layout shell JSON/HTML is retrieved before click.

Step 2: Instant Render (0ms)

On click, the header, sidebar, logo, and skeleton fallbacks load immediately.

Step 3: Dynamic DB Streaming

The server fires the mongodb database query under the `` boundary, streaming the rows to the client browser in real-time as they resolve.

Docker Standalone & Volume Persistence Guide

Configure file volumes correctly to prevent losing product images and catalogs when upgrading containers.

File Data Risk

By default, files uploaded in the dashboard (like catalog PDFs and product images) are saved inside the container filesystem path:

/app/public/upload/

If the container is updated, rebuilt, or restarted on Coolify, all files stored in this path are lost because container disks are ephemeral.

Persistent Volumes Solution: We map a host directory or named Docker volume to `/app/public/upload` inside the web container. This keeps files safely stored on the host host machine permanently.

Recommended docker-compose.yml Configuration

Mount the volumes properly under the `web` service configuration blocks as shown below:
